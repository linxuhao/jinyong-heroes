# Development note — 2026-09-15

武虾传奇 · Myth of Kungfu Shrimp

The last public update here was dated 2026-09-05, and the demo build on the
`demo` branch was made on 2026-09-04 from source commit `6f3bc60`. Development
did not stop; the publishing did. This note closes that gap. Everything below
names the commit that carries it, so anyone reading can check the claim against
the history rather than take our word for it. The private source range is
`6f3bc60..5b598e9` — 779 commits.

Two honest framings before the list. First, this is text only: the playable
demo is **not** republished today, because the demo's content boundary is being
reworked and shipping a build ahead of that rework would publish the wrong
thing. Second, most of the work in this range is unglamorous — it is the kind
of repair that stops a game losing your progress. That is the part of a
development log that usually gets skipped, so it goes first.

## Your progress stops disappearing

- **A refused save no longer destroys the save you already had** (`f4bbda3`).
  The save writer deleted its recovery copy one line *above* the step that
  publishes the new file. A publish that was refused then found no backup, took
  the "there was no previous file" branch, and deleted the file it had just
  promoted — the save that existed before you pressed the button was gone, with
  nothing left to restore from. A second bug in the restore path removed the
  real file and then deleted the backup whether or not the restoring copy had
  worked, so a failure left *neither* copy. Both paths are repaired; the backup
  is now kept when a restore copy fails. Stated plainly: no envelope this build
  writes can actually be refused at that step, so this was defensive safety
  rather than a repair of an observed loss — but it was one code path away from
  being real.

- **A reloaded month cannot hand out its 机缘 a second time** (`f3e7c56`).
  Reloading a month re-granted the reward that month had already given. Save,
  reload, collect again was a working exploit. It is not any more.

- **A new campaign inherits nothing from the last one** (`ad6dda4`). Starting a
  new game reset your profile, dice and decks but left the growth ledger and
  its damage marker behind, so allocation could arrive already refused in a
  brand-new game and an ordinary save could write the previous campaign's
  damaged marker into it. The same change stopped the growth panel from
  overwriting a real failure message with the generic "pick a target"
  instruction — a failed write used to reach you as advice.

- **Every campaign now carries its own identity from the moment of creation**
  (`a4c3130`), minted from the engine's cryptographic RNG and independent of
  the game's seeded dice — so two campaigns rolled from the same seed stay
  bit-identical in their randomness while remaining two distinguishable saves.

## The month is the plan

- **The monthly plan became the month itself** (`f714f5f`, with the segment
  work in `033c191`). The plan used to be one row on a list of ten, so a month
  opened on the action list and you had to go *find* the plan. Now every route
  that reaches a spendable month — accepting the card, reloading, the
  controller's own staging — lands on the plan, seeded with one real row per
  declared slot, so an untouched month is already confirmable and the action
  list is one Back away. A confirmed month refuses its rows by name instead of
  quietly spending itself twice.

- **A commission is raised before it is sealed** (`189c217`), so you see what
  a plan row is going to cost and do before it becomes a fact.

- **The yearly event reroll is reachable again** (`c53183a`). Making the plan
  the month removed the screen the reroll button used to live on, which left
  the reroll unreachable — a feature stranded by its own route being deleted.
  It is now a row on the travel offer, spending the same single reroll budget,
  with the replacement offer, the randomness it consumed and the used counter
  landing in one write.

## What reaches the screen

- **The game stopped speaking to you in its own internal vocabulary**
  (`98eb07d`). The plan editor printed raw internal ids in its target rows
  (`shaolin_yijin_d`) and the contract's own error codes in its status line
  (`slot_count_mismatch`). The reason it survived is worth saying: nothing in
  the project looked at what a player-visible string *looks like*. The two
  known cases turned out to be the visible part of 15 display sites carrying an
  internal identifier onto a screen. The codes still exist where code should
  read them; what changed is what reaches a label, and the shared wording table
  went from 75 refusal codes to 119 so there is a sentence for each. A check
  now fails the build when a module whose verdicts reach a screen emits a code
  nobody has written a sentence for.

- **The fighters fit on their tiles, and their nameplates stop covering them**
  (`ffa8760`). The player character was the one body in the prologue without
  the one-tile clamp its opponents had, so it drew two tiles tall and reached
  into the row above, under the neighbours' name plates. Separately, the
  nameplate packer resolved plate-against-plate but not plate-against-*body*,
  which is how one unit's plate ended up parked on the player's head and the
  player's own plate on its chest. Earlier in the range, neighbouring units
  stopped sharing a single nameplate and HP readout (`724c000`).

- **One damage rule, in one place** (`bde1ecc`), and **a basic attack now
  honours the reach the character declares** (`d28843c`).

## Co-op, and what the demo is

Co-operative play is a development goal and is still not a released feature —
but it stopped being a sketch in this range.

- **A table of one to four players, with an identity and a way out**
  (`b75f31e`), reached from a title-screen entry (`703041f`).
- **A host can name a table, save it, and continue it later** (`96854c8`): the
  ledger, the seats and each player's read position survive reopening
  (`0c87131`).
- **A co-op table can reach a live encounter built from the profile you
  actually played** (`27a470a`), with the turn boundary recorded as a
  durable command (`7465073`) and the round reset reaching the record rather
  than only memory (`35a472e`).
- **One game, one code path** (`21f49d1`). This is a user direction rather than
  a technical one, and it deleted work: the demo used to get its own prologue
  ending, which meant maintaining a second experience alongside the first. That
  ending is gone. The demo is now the same game, and the only difference a
  player meets is that the co-op entry is visible and refuses to open.

## How we check our own work

Two changes in this range are about the tests rather than the game, and they
belong in a public log because they are the reason the rest of it is
trustworthy.

- **A check that ran on four files out of 164 was reporting on four files**
  (`af695f4`). A previous commit had fixed the checker's sensitivity and left
  its window at a four-scenario sample; a green result from that sample is a
  verdict about the sample. It now runs over every scenario, with the scenario
  count itself asserted so a broken file glob cannot make it pass by finding
  nothing.
- **The author of a scenario no longer picks the node that judges it**
  (`351c43a`).

## What is next

A reliable playable slice where different training decisions visibly change
combat, and the demo's content boundary settled well enough that the public
build can come back. The demo republish is deliberately held behind that
boundary work; when it moves, it will be said here.
