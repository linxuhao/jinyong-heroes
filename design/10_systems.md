# Core systems

## 1. 属性

五项。前三项进战斗,后两项只在养成里起作用。

| 属性 | 战斗中派生 | 养成中的意义 |
|---|---|---|
| 根骨 | 气血上限、防御 | 硬扛型成长 |
| 内力 | 内力池、内功威力 | 招式的消耗资源 |
| 身法 | 移动力、先攻、闪避 | 走位型成长 |
| 悟性 | — | 学功法的速度 |
| 福缘 | — | 事件与奇遇 |

派生公式待战斗实装时定稿;当前教程战的角色数值是**直接给定**的
(见 `20_content.md`),不经公式。

**内力池既存也耗。** 内功产出的内力值(杨过 180)存在数据里、显示在界面上;
出招按 `20_content.md` 的招式内力消耗表**扣减内力**——内力不足则无法出招,
按钮进入「内力不足」(`no_energy`)状态。普攻消耗 0,是玩家的保底动作,内力归零时仍可普攻(见 `90_decisions.md`)。重剑无锋是**免费基础招**(理由见
`20_content.md` §7.3),内力池**一场战斗内不回复**(回复机制留待后续轮次定义)。

## 2. 功法:内功与外功

| | 产出 | 战斗中表现为 |
|---|---|---|
| **内功** | 属性加成、内力池、被动 | 数值底盘 + 常驻效果 |
| **外功** | 招式(主动技能) | 技能栏上按的东西 |

**外功是技能包。** 外功的等级决定它练满后给几个招式:

| 外功等级 | 练满给几个招式 |
|---|---|
| 丁 | 1 |
| 丙 | 2 |
| 乙 | 3 |
| 甲 | 4 |

**招式不限于伤害技。** 位移(轻功)、防御姿态(横练)、增益、控制都是招式。
在回合制格子战里位移技和防御技与伤害技等价。

### 2.1 外功门类(10 类)

刀 · 剑 · 长兵(枪棍棒杖) · 拳掌 · 指 · 暗器 · 轻功 · 横练 · 奇门毒 · 乐器

爪法、腿法并入拳掌,不单列。鞭法暂不设。

### 2.2 近战 / 远程:看武器,不看招式

**一个招式是近战还是远程,由它所属外功的门类决定,与招式的形状、射程、
伤害都无关。** 十门类各属一边:

| 近战 | 远程 |
|---|---|
| 刀 · 剑 · 长兵 · 拳掌 · 轻功 · 横练 | 指 · 暗器 · 奇门毒 · 乐器 |

指法归远程,因为它打出去的是**外放的指力**(一阳指、六脉神剑),不是接触伤害。

**为什么定这条。** 上一版把这件事交给"解算时两个单位的距离",于是一个
直线 4 格的招式算近战、一个全场音波也算近战,得靠一张边界枚举表打补丁,
而那张表每加一个新招式就要重新拍一次脑袋。改成看武器之后,规则是一行,
新招式一进来就自动分好边——它属于哪门外功是本来就要填的字段。

推论(不要再单独判):
- 打**范围**不代表远程。降龙的直线 3 格、玄铁的十字 2 格都是近战。
- 打**贴脸**不代表近战。玉箫点穴射程 1 也是远程,因为玉箫是乐器。
- 一个人的近战/远程是**逐招式**的,不是逐角色的——若他同时修了拳掌和暗器,
  两边的招式各按各的门类算。

普攻按**该角色主修外功**的门类算。

## 3. 等级与前置

功法分**甲乙丙丁**四级,甲最高。前置**级联**,且**按门类**计算——
甲级剑法要的是剑法的乙丙丁,拿刀法顶不了。内功自成一类,同规则。

| 等级 | 前置 |
|---|---|
| 丁 | 无 |
| 丙 | 同门类丁级满 ×1 |
| 乙 | 同门类丙级满 ×1、丁级满 ×1 |
| 甲 | 同门类乙、丙、丁各满 ×1 |

## 4. 发挥度

一张查表,没有连续公式。这是本作对《太吾绘卷》武学发挥度的**简化**:
砍掉相性、境界等一切连续量,只留"前置齐了没有"这个可判定的事实。

**发挥度 = 前置完成度 × 属性加成**

| 前置缺几门 | 基础 |
|---|---|
| 缺 3 | 0.6 (失常) |
| 缺 2 | 0.7 (失常) |
| 缺 1 | 0.85 (失常) |
| 齐全 | 1.0 |

| 前置齐全时,同属性几门 | 加成 |
|---|---|
| 0 / 3 | ×1.0 (正常) |
| 1 / 3 | ×1.1 |
| 2 / 3 | ×1.2 |
| 3 / 3 | ×1.3 (**超常**) |

取值区间 **0.6 ~ 1.3**。

### 4.0 乘数作用在什么上:一条规则,没有例外

> **每一个数字,吃它自己出身那门功法的发挥度。**

外功产出招式 → 招式吃**该外功**的发挥度。
内功产出属性、内力、被动特征 → **普攻**(派生自攻击属性)与**特征产生的伤害/
回复**吃**该单位主修内功**的发挥度。

| 数字 | 吃谁的发挥度 |
|---|---|
| 招式伤害 / 治疗 / 护盾 | 该招式所属**外功** |
| 招式施加的持续伤害,每轮跳数 | 该招式所属**外功**(应用时定值) |
| **普攻伤害** | 该单位主修**内功** |
| **强大特征的伤害与回复**(弹指神通反击、蛤蟆反震、神雕之力回复、一阳续命回复) | 该单位主修**内功** |

**不吃乘数的**:冷却、射程、击退格数、持续轮数、位移格数、内力池,
以及**一切百分比**(减伤率、命中率、暴击率)——乘数作用在「多少」上,不作用在
「几成」上。把 −50% 减伤乘以 1.3 是没有意义的。

这条规则替代了"招式吃、普攻不吃、被动不吃"那种逐条裁定——逐条裁定每加一个
新东西就要再裁一次,而且裁得对不对没人验得出来。

例:西毒的中毒 8/轮 在 1.3 下是 `round(8 × 1.3) = 10`/轮;杨过普攻 30 → **39**;
弹指神通反击 10 → **13**;神雕之力每轮回复 20 → **26**。

### 4.1 3/3 的额外解锁

满属性专精的回报**不只是数字**,而是一个新动词:

| | 3/3 解锁 |
|---|---|
| **内功** | **强大特征** —— 一条常驻被动 |
| **外功** | **绝招** —— 一个战斗主动技(即该外功的第 4 个招式) |

梯度(×1.1 / ×1.2)负责一路上的正反馈,解锁负责终点。

### 4.3 伤害结算管线(两段,各取整一次)

发挥度是**攻击侧**的乘数,减伤是**防御侧**的乘数,两者分属不同阶段,
中间隔着"这一击打出去多少"这个数。

```
攻击侧   基础值 × 发挥度  →  round()  →  输出值
                                          ↓  apply 到目标身上
防御侧   输出值 × (1 − 减伤)  →  round()  →  实际扣血
```

- **攻击侧先算完、取整,再交给目标。** 目标的护甲、减伤特征(丐帮铁骨 −15%、
  神雕之力对近战 −50%)是在 apply 的那一刻才参与的,不能提前混进发挥度里。
- **两段各 `round()` 一次**,不是只在最后取整一次。理由是攻击侧的"输出值"是
  一个要被界面、日志、断言读到的真实数字(飘字显示的就是它),它必须是整数;
  减伤之后同样会出小数,所以再取一次。
- **`round()` 就是 GDScript 的 `round()`:逢半远离零。** 半数情况不是理论问题——
  凡是个位为 5 的基础值乘 1.3 都精确落在 .5 上,而 45、25、35、15 都在内容表里。
  引擎实测:`45 * 1.3` 在 double 里**就是精确的 58.5**(不是 58.4999…),
  `round()` 给 **59**;`25 * 1.3 = 32.5 → 33`;`35 * 1.3 = 45.5 → 46`。
  实现一律写 `round(v * mult)`,不要自己拼 `int(v * mult + 0.5)`。
- 例:重剑无锋 45 × 1.3 = 58.5 → `round()` = **59** 输出;打在丐帮铁骨身上
  59 × 0.85 = 50.15 → `round()` = **50** 实际扣血。
- 无视减伤的招式(一阳指"无视 −20% 减伤")在防御侧跳过对应的减伤项,
  攻击侧不变。

### 4.2 属性

**阴 · 阳 · 刚 · 柔** 四种。功法各带一种。

**属性相克本作不做**——只做同属性前置加成。相克是一层独立的复杂度,
留待战斗系统跑顺之后再议(见 `90_decisions.md`)。

## 5. 回合制战斗

### 5.1 回合结构

- 每一**轮**里,每个存活单位按**先攻序**行动一次。先攻由身法决定,高者先动。
- **并列用稳定排序,后加入的排后面。** 六个初始先攻值互不相同,但碧海潮生会让
  敌方先攻 −20 持续两轮,**并列是战斗中被制造出来的**。Godot 的
  `Array.sort_custom()` 不保证稳定,并列时顺序会在两次运行之间变,playtest 的
  确定性就没了。所以:按先攻降序做**稳定**排序,并列者保持注册顺序——
  先加入战场的排前面,后加入的排后面。
- 先攻的变化(碧海潮生的 −20)**在下一轮生效**:每轮开始时对存活单位快照一次
  行动顺序,本轮之内不再重排。
- 一个单位的**回合** = **移动**(≤ 移动力格)+ **一个动作**(普攻 / 招式 / 等待),
  然后结束回合。移动与动作的先后不限。
- 移动是**点击驱动**:左键点空格走过去(点敌格仍是攻击,点自己格无操作),
  右键**退回**本回合移动起点。方向键 / WASD 保留为快捷方式,不再是主交互。
- **试走 → 反悔 → 出手即锁定**:回合开始快照 `turn_start_grid` /
  `turn_start_moves_left` / `turn_start_moved`,右键退回恢复到该快照并返还移动力。
  成功执行一个动作(引擎置 `acted == true`)即**确认移动**——此后右键退回被拒
  (「已出手,无法退回」),但**仍可继续移动**:锁定只锁退回、不锁移动,
  「移动与动作先后不限」不变。结束回合同样锁定。退回经同一共享入口:右键点击
  **和** HUD「退回」按钮(`UndoButton`)同一语义、同一锁定规则。
- 全部单位行动完毕,进入下一轮。

### 5.2 冷却与持续效果

冷却以**回合**计,不以秒计。旧的秒制换算:

| 旧(秒) | 新(回合) |
|---|---|
| 3.0 | 2 |
| 4.0 | 3 |
| 5.0 | 4 |
| 6.0 | 5 |
| 15.0 | 10 |

**冷却在该单位自己回合开始时递减**,不是每轮开始给所有人一起减。
"冷却 2"因此意味着"这个单位每隔一个自己的回合能用一次"。

中毒等持续伤害同样在**受害者自己回合开始时**结算,持续时间以回合计
(旧 4 秒 → 3 回合,旧 3 秒 → 2 回合)。

一个单位回合开始时的结算顺序:**冷却递减 → 持续伤害/治疗结算 → 常驻回复
(神雕之力 +20、一阳续命 +10)→ 该单位开始行动**。

### 5.3 平衡目标(教程战)

**8 ~ 12 轮结束,玩家以剩余气血 15% ~ 40% 获胜。**

这是一个可断言的目标,`playtest/terminal_victory_8_12_rounds_hp_15_40.yaml` 应当据此写。
超出上限说明玩家太弱,低于下限说明太强。

### 5.4 战术意图(教程战)

五绝同场,人多。玩家的解法是**引诱聚拢再范围清场**——这也是教程要教会的
核心动词。单体输出打不完 5 个人是**设计意图**,不是数值失衡。

### 5.5 范围技的原点

范围形状**不是一律以施术者为心**。每个范围招式要显式声明它的原点:

| 原点 | 含义 | 例 |
|---|---|---|
| `self` | 以施术者所在格为心 | 四海无量(半径 2)、黯然销魂十七式(相邻) |
| `target` | 以被指定的目标格为心 | 落英缤纷(射程 3,以目标格为心的 3×3) |
| `landing` | 以位移落点为心 | 徘徊空谷(跳 3 格,落点相邻)、飞龙在天 |

**"十字 N 格"是臂长 N 的十字**(十字 2 格 = 中心 + 四个方向各 2 格 = 9 格),
不是固定的五格。"半径 N"按切比雪夫距离(方形)算。

**范围技不误伤同阵营。** 伤害类范围只命中施术者的敌对单位,治疗类只命中友方。
五绝是五绝,不会因为站位被骗就一掌拍在同伴身上——那不像他们。代价是"把敌人
引成一坨"只对玩家单方面有利,这是接受的。

## 6. HUD 硬要求

**技能按钮必须直接显示该招式当前的发挥度**(失常 / 正常 / 超常 + 乘数)。

玩家看不见的系统等于不存在。这是《太吾绘卷》那套最被诟病的地方,
也是我们唯一能对它写断言的地方。
